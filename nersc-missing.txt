three of the four requirements map cleanly onto what's here, with one genuine gap.
  The full accounting for the NERSC dp2 repo:

  1. deep_coadd_cell_predetection → deep_coadd + .to_legacy_cell_coadd(). The NERSC deep_coadd is
  the newer lsst.images.cells.CellCoadd serialization, and calling to_legacy_cell_coadd() on it
  returns a genuine MultipleCellCoadd — verified on tract 2395 patch 53 band i: 484 cells, and
  cell.inputs carries the (visit, detector) identifiers your check script reads (e.g.
  2025071900591/83). Its delivered image state has no coadd-level background applied (lsst-mdet
  applies 'object' explicitly), consistent with predetection semantics — though if exactness
  matters it's worth one numerical A/B against USDF on a shared patch. For the inputs alone there
  are lighter routes: dc.provenance (inputs/contributions tables) or the run-wide
  deep_coadd_input_summary table (tract, patch, visit, detector, weight, goodpix, band; 21.2M
  rows).

  2. deep_coadd_background → dc.backgrounds['object']. It's attached to the coadd rather than a
  separate dataset; render with bg.field.render(dc.bbox). The stored description matches the
  object-catalog background ("intentionally oversubtracts… to reduce blending and ensure
  scattered light is subtracted").

  3. visit_summary — present, VERIFIED for the actual input visits (instrument LSSTCam).

  4. preliminary_visit_image_background — genuinely absent. The repo has no visit-image or
  visit-background dataset types at all, so the per-(visit, detector) background models can't be
  reconstructed locally. Three options: (a) transfer just the needed subset from USDF — you have
  access there, the models are small files, and deep_coadd_input_summary gives the exact (visit,
  detector) list per tract to target; (b) an approximate coadd-level stand-in that's already
  here: the second stored background, 'pretty', whose own description says subtracting it "will
  generally add flux, correcting for most oversubtraction problems" — i.e. it's a coadd-level
  estimate of much of the light the visit backgrounds took, with stated caveats about scattered
  light and variable-source contamination; (c) run the algorithm degraded without the visit-level
  restore.

  So a thin adapter in lsst-starsub — read deep_coadd, convert to legacy, pull the object
  background from the attachment, keep visit_summary as-is, and gate the visit-background stage
  on availability — gets everything except the visit backgrounds running at NERSC unchanged. Want
  me to write that adapter (and/or set up the USDF transfer list for option a)?
